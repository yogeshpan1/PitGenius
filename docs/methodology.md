# PitGenius — Methodology & Results

*Written to research-documentation standard. Every number in this file is
reproducible from the scripts referenced; every claim includes its failure
modes.*

## 1. Data

- **Source**: F1 official timing API via FastF1 (public, no key).
- **Scope**: race sessions (code `R`), seasons 2021–2025, all rounds that
  had been run at ingestion time.
- **Storage**: SQLite (`data/pitgenius.db`) — tables `races`, `laps`,
  `pit_stops`, `results`, plus an ingestion `manifest` making the pipeline
  idempotent and resumable.
- **Cleaning** (`src/pitgenius/data/clean.py`):
  - Lap times converted to seconds; laps with missing/zero time dropped
    from modeling but retained in storage.
  - Out-laps flagged; tire compound normalized to {SOFT, MEDIUM, HARD,
    INTERMEDIATE, WET}; unknown compounds → UNKNOWN.
  - Track status preserved per lap for green-flag filtering.
- **Known gaps**: 2021 R12 (Belgium) has no racing laps — recorded as a
  manifest error by design, not silently skipped.

## 2. Tire degradation model (Stage 3)

- **Target**: lap-time delta vs the driver's own median clean lap in that
  race. This removes car performance and driver skill — strategy models
  must learn *relative* degradation, not absolute pace.
- **Features**: tire age, compound, fuel proxy (0.033 s/lap of fuel burn,
  linear), circuit identity as categorical.
- **Model**: three LightGBM quantile regressors (α = 0.1/0.5/0.9).
- **Validation protocol**:
  - **A. Leave-one-race-out** across all ingested races (interpolation).
  - **B. Season holdout**: train < 2025, test 2025 (deployment scenario;
    headline number).
- **Metrics**: MAE/RMSE on P50, pinball loss per quantile, P10–P90
  coverage (target ≈ 80%), mean interval width.
- **Results**: see `reports/degradation_validation.json` (generated by
  `scripts/train_degradation_model.py`). Per-race breakdowns are included
  unfiltered, including the worst races.

## 3. Undercut / overcut calculator (Stage 4)

Definitions are fixed once in `src/pitgenius/analysis/undercut_history.py`
and reused everywhere. The calculator does cumulative-time accounting:

```
gap_after = g + fresh_delta − old_delta − (P_A − P_B)
```

with fresh/old deltas sampled within the model's P10–P90 band and pit-loss
difference ~ N(0, 0.5²). Output: P(position flip) + P10/P50/P90 gap after.

**Backtest**: every historically detected attempt scored with a model
trained only on prior seasons. Reported: Brier score vs base-rate baseline,
log loss, calibration buckets, per-attempt records. See
`reports/undercut_backtest.json`.

## 4. Monte Carlo simulator (Stage 5)

- Full field (20 cars); candidate strategies ride along as focal cars with
  common random numbers so comparisons share pace/SC/pit draws.
- Safety-car incidence per circuit from historical TrackStatus transitions,
  shrunk toward the global mean (k=3); period counts Poisson, lengths normal.
- Pit loss halved under SC/VSC (empirical).
- Outputs: P(win), P(podium), expected points, finishing-position
  P10/P50/P90.

## 5. Formal backtest (Stage 6)

For each test-season race: era-appropriate model (prior seasons only),
three canonical one-stop strategies + the winner's actual reconstructed
strategy simulated; recommendation compared against reality. All races
reported, hits AND misses. See `reports/backtest_report.md`.

## 6. Live predictions (Stage 7)

Pre-race payload written once with UTC timestamp + SHA-256; re-publishing
raises unless explicitly archiving. Post-race scoring verifies the hash
before grading. The loop cannot produce real predictions until a real
session runs — by design it was built to be runnable the moment one does.

## 7. Threats to validity (read before quoting any number)

1. **Circuit identity is keyed by round number**, not track — calendars
   move; round 5 is not always the same GP.
2. **Fuel proxy is linear**; real fuel effects interact with tire state.
3. **Pit-loss estimates** come from out-lap deltas; traffic noise remains.
4. **Undercut detection** requires adjacency in reconstructed running
   order; cumulative-time proxies misorder cars after SC restarts.
5. **Simulator pace spread** (σ=0.9 s field sd) is a simplification; real
   fields have team clusters.
6. **No weather features yet** — wet races will degrade model validity.
7. **Sample sizes are small** for per-circuit claims; shrinkage helps but
   does not eliminate it.
